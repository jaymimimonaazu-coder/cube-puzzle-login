# NEON LATTICE / Cube Passcode

ネオン管のスケルトン立方体。**6面 × 4×4升 = 96セル**から、**各面2箇所ずつ計12箇所**を選んで解錠するパスコード認証のデモです。

回転させるのではなく、面のセルを直接タッチするボタン式です。

## 鍵空間

```
1面あたり : C(16,2) = 120 通り
6面すべて : 120⁶ = 2,985,984,000,000 通り（約2.99兆） ≈ 41.4 bit
```

ランダム英数字7文字とほぼ同等の強度です。参考までに、4桁PINは13.3bit、Androidのパターンロックは18.6bitです。

## 使い方

初回は **ENROLL（登録）**、2回目以降は **AUTHENTICATE（認証）** モードで起動します。
正解はソースに埋め込まれておらず、自分で登録した配置が鍵になります。

| 操作 | 動作 |
|---|---|
| ドラッグ | 立方体を回転 |
| セルをタップ | 選択／解除（各面2箇所まで） |
| 12箇所そろう | 自動で登録または照合 |
| CLEAR | 選択を消す |
| 忘れた | 登録を消去して再登録 |

登録した配置は **SHA-256 ハッシュにして localStorage に保存**します。生の配置は保存しません。

### 判定ルール

- **面内の入力順は問いません**（`{0,5}` と `{5,0}` は同一）
- **面をまたぐ順序も問いません**（各面2箇所そろえばよい）
- **5回失敗すると15秒ロック**（レート制限のデモ）

## 起動

ES Modules と Three.js の CDN を使うため、ローカルサーバー経由で開いてください。

**Windows（PowerShell）**
```powershell
python -m http.server 8000
```

**macOS / Linux**
```bash
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。

## 実装

| 要素 | 技術 |
|---|---|
| ネオン管 | 細いシリンダーの発光コア＋加算合成のグローチューブ（12辺＋8ノード） |
| ブルーム | `UnrealBloomPass`（strength .62 / radius .38 / threshold .34） |
| セル | 面ごとに法線・u軸・v軸を定義して 4×4 を配置。`DoubleSide` の半透明プレーン |
| 奥面の処理 | 面法線とカメラ方向の内積で濃淡を毎フレーム更新。裏面は 0.14 倍まで沈める |
| 誤タップ防止 | レイキャストの結果から、手前を向いた面（facing > .55）のセルのみ採用 |
| ハッシュ | Web Crypto API `SHA-256` |

スケルトン構造は奥の面まで透けるため、**濃淡制御とレイキャストのフィルタが視認性・操作性の要**になっています。

## 本番で使う場合の注意

これは UI / インタラクションの PoC です。実運用では以下が必須です。

| 項目 | 対応 |
|---|---|
| 照合場所 | **必ずサーバー側**。localStorage の比較はデモ用 |
| リプレイ対策 | サーバー発行の challenge / nonce をハッシュに混ぜる |
| レート制限 | サーバー側で試行回数を管理（クライアント側のロックは回避可能） |
| 位置づけ | 41.4bit は単独運用も可能な水準だが、**MFAの1要素**として使うのが安全 |
| 覗き見対策 | スケルトンは反対面の押下が透けて見える。12箇所の入力は観察されやすい点に注意 |

### 鍵空間を広げたい場合

| ルール | 組み合わせ数 | ビット |
|---|---|---|
| 現在（各面2升・順不同） | 2.99兆 | 41.4 |
| 面内の2升に順序を付ける | 191兆 | 47.4 |
| 12回の押下すべてに順序を付ける | 1.43垓 | 70.3 |

順序を導入すると強度は上がりますが、記憶負荷も上がります。
