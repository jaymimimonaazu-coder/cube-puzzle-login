# Cube Passcode — 立方体型インタラクティブパズル

> [!WARNING]
> このプロジェクトは3Dインタラクションとセキュアコーディングを学ぶための実験的デモです。
> 本番認証、暗号鍵生成、ウォレットシード、金融・医療用途には使用しないでください。
> AI支援レビューと自動テストは、第三者監査や安全性保証を意味しません。

3D立方体の6面（各面4×4＝16升）から**各面2箇所ずつ、計12箇所**を選んで解錠する、
空間記憶を使ったパズル型インターフェースの実装です。

**macOS**
```bash
open preview.html
```

**Windows (PowerShell)**
```powershell
Start-Process .\preview.html
```

---

## これは何か / 何ではないか

| | |
|---|---|
| ✅ **これは** | 3Dインタラクションの実装例、セキュアコーディングの学習教材、体験型コンテンツの部品 |
| ❌ **これではない** | 「次世代認証システム」。パスキー(FIDO2)や生体認証の代替にはなりません |

**この方式は新しいものではありません。**
3D空間やグリッド上の位置を選択するグラフィカル認証の広い技術概念には、
2006年頃からの研究と複数の特許文献があります（後述）。
なお、本実装について特許法上の新規性・進歩性は判断していません。

Microsoft Picture Password など、画像上の位置やジェスチャーを利用する
グラフィカル認証方式には商用実装の前例があります。

グラフィカルパスワード一般には、選択位置の偏り、観察攻撃、
スマッジ攻撃、長期的な記憶保持などの課題が研究されています。
本方式も同様の課題を受けます（[`VERIFICATION.md`](VERIFICATION.md)）。

このリポジトリの価値は、方式の目新しさではなく
**「作って、攻撃して、直して、記録した」一連の過程が残っていること**です。

> `preview.html` は体験・展示用のスタンドアロンデモです。

> サーバー版のセキュリティ特性を再現するものではありません。

### サーバー版を動かす

**Linux / macOS**
```bash
cd server
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --port 8000
```

**Windows (PowerShell)**
```powershell
Set-Location server
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --port 8000
```

→ `http://localhost:8000`

画面上で **ENROLL（新規登録）** または **AUTHENTICATE（認証）** を選択します。
登録状態を外部公開しないため、ユーザー名からの自動判定は行いません。

サーバー版では、**正解の平文をフロントエンドのソースへ埋め込んでいません。**

## 組み合わせ数

```
1面あたり : C(16,2) = 120 通り
6面すべて : 120⁶ = 2,985,984,000,000 通り（約2.99兆） ≒ 41.44 bit
```

> [!CAUTION]
> 暗号学的乱数生成器で各面の組を独立かつ一様に生成する `generate_random()` の出力については、
> 生成時点の理論エントロピーが約41.44 bitです。
> **人間が選択・変更した場合や、生成結果が漏えいした場合にはこの値を適用できません。**

### 記憶できるかは未検証です

グラフィカルパスコードの記憶研究の一例では、参加者が最大8枚の画像による
パスコードについて良好な項目保持を示したと報告されています。
ただし、画像の認識課題と本方式の空間位置の再現課題は異なるため、
**この結果から本方式の上限を8項目と判断することはできません。**

記憶保持率は方式や実験条件によって大きく異なります。
**本方式について、翌日・1週間後の再現率はまだ測定していません**
（[`VERIFICATION.md`](VERIFICATION.md)）。

なお本設計では、選択項目を減らすと理論鍵空間も小さくなるため、
記憶負荷と鍵空間の間にトレードオフがあります。

## AI支援コードレビューの記録

Claude と Codex を用いた **2系統のAI支援コードレビュー**を実施し、
指摘された13項目について修正と回帰テストを行いました。

> [!NOTE]
> これは専門事業者による第三者セキュリティ監査、侵入テスト、
> または本番利用の安全性保証を意味しません。

| 深刻度 | 件数 | 代表例 |
|---|---|---|
| 高 | 3 | レート制限の競合バイパス、無認証でのアカウント乗っ取り、強度判定の過大評価 |
| 中 | 6 | 巨大入力によるDoS、ユーザー列挙、ロックアウトの第三者悪用 |
| 低 | 4 | 残り試行回数の漏洩、到達不能な型検証、CORS方針の未定義 |

修正後の検証:

- **pytest 50件すべて合格**（レビュー前は16件）
- AI支援レビューで指摘された既知の攻撃シナリオについて、修正後の回帰テストがすべて成功
  - 並行30リクエスト → 検証到達5回・ロック25件（**修正前は30本すべて通過**）
  - 無認証での上書き → 409 / 無認証削除 → 401（**修正前はどちらも成功**）

> E2Eテストの成功は、ブラウザとAPIの主要動作を確認したものであり、
> システム全体の安全性を保証するものではありません。

詳細:
- [`AUDIT_FINDINGS.md`](AUDIT_FINDINGS.md) — 2系統のレビュー結果の突き合わせと対応状況
- [`REVIEW_REQUEST.md`](REVIEW_REQUEST.md) — 外部AIへ渡した検証依頼書
- [`CODEX_REVIEW.md`](CODEX_REVIEW.md) — Codex のレビュー結果

### レビューで分かった重要な教訓

**「単一のパスコードからエントロピーは推定できない」**

当初は配置の強度を「推定◯bit」と表示していましたが、これは誤りでした。
例えば3種類の配置を繰り返すだけの `[0,1][4,5][8,9]×2` は
実装上30.44bitと判定されて登録を通過しますが、
「3種から各面を選ぶ」という生成規則なら候補は 3⁶ = 729 ≒ 9.5bit しかありません。

現在は bit 値を返さず、**既知の弱い規則に該当するかだけを検査**しています
（強度の保証ではなく、明らかな悪手を弾くフィルタ）。

## 仮に運用する場合の最低要件

`server/` はレビューと回帰テストを経ていますが、
**そのまま本番の認証基盤として使うことは想定していません。**

- **HTTPS/TLS必須**（パスコードは認証時にブラウザからサーバーへ送信されるため）
- 複数プロセス・複数台構成に対応した共有セッションストア（Redis や DB など）、
  有効期限、失効、ローテーション
- 監査ログと異常検知
- 面の識別を色だけに依存させない（色覚特性への配慮）
- **多要素認証の1要素として使う**（単独運用しない）
